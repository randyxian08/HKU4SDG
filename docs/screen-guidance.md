# AI 屏幕引导（0.2.0）

更新于 2026-10-18。本轮目标是补上“模型理解当前页面并选择下一步”，扩展到四项固定流程之外。此前模型只收到目标文字，不能把读取控件说成模型已经看懂屏幕。

## 用户怎样使用

1. 首页说出或输入目标，再点“看屏幕，帮我下一步”；固定意图匹配返回不支持时，也会进入设置页。
2. 选择已安装的 App，写清想完成的事。本次引导须单独同意把所选 App 的可见控件文字交给云端模型；可以另选提供当前窗口截图。
3. 点“同意并打开 App”。应用读取当前可见控件，模型只选择一个下一步；本机核对目标仍存在，才圈出来。
4. 用户亲手点击、输入或滑动。页面内容、位置或选中状态变化会撤销旧圈画，再重新判断；没有自动代点、输入或提交。
5. “听一次”重播模型生成的本步语音文案；“看下一步”主动重试。“更多”可暂停、换位置、补充目标、调整语言或结束。
6. AI 判断目标已经出现时，仍须用户确认。AI 的完成判断不是系统级结果检测。本次屏幕引导的页面内容和目标不写入练习记录，四项固定任务的原记录仍保留。

文字与播报继续使用两项独立语言设置。输入可沿用首页语音转写和检查；本轮不增加持续监听或让语音识别自动提交目标。

## 与固定引导的区别

| 内容 | 四项固定流程 | AI 屏幕引导 |
|---|---|---|
| 用户目标 | 映射到四个登记任务 | 用户输入目标并选择 App |
| 模型输入 | 目标和输入语言 | 目标、当前 App、可见控件及状态；截图另行选择 |
| 下一步 | 本地流程及页面条件决定 | 模型从本次快照的控件中选择一步 |
| 圈画依据 | 已登记的本地匹配规则 | 返回控件 ID；本机核对页面指纹、状态和实际位置 |
| 完成 | 已登记结果检测后等待确认 | 模型根据当前可见内容提出完成，再等待用户确认 |
| 无法理解 | 撤圈，说明页面不在固定范围 | 撤圈，请用户补充目标、重试或结束 |

新模式没有为 F-Droid、时钟等 App 编写任务选择器或预设步骤，也没有按应用名称返回某个答案。它依赖目标 App 提供的可见无障碍控件，因此不等于任意 App 都能用。截图仅辅助理解，不能让模型编造没有对应控件的坐标。

## 页面到模型的实际链路

`ScreenGuideController` 只在用户启动的会话内读取所选包名的活动窗口；切换到其他 App 后撤圈并暂停，不继续发送其他 App 页面。暂停会取消排队与本地等待的请求，但已经发送给供应商的数据无法撤回。

每次收集最多 80 项可见控件，含临时 ID、文字／描述、控件类型、可点击／可编辑／可滚动／启用状态、坐标和选中／焦点／勾选状态。编辑框的实际内容不加入模型节点文字，只提供是否已经输入。遍历上限为 450 项，无法完整核对或没有可靠控件时保留失败提示。

若选择截图且系统为 API 34 以上，使用 Android 的 `takeScreenshotOfWindow` 获取目标窗口，缩至最多 720 像素宽的 JPEG。只发送内联图像，不接受远程图片 URL。截图失败时使用控件信息；受保护窗口不会被绕过。

App 经 Debug 模拟器的 `10.0.2.2:8765/screen-step` 请求电脑代理，再由 `screen_planner.py` 调用现有豆包 `doubao-seed-2-0-mini-260428`。开发密钥保留在宿主机。本轮仍没有交付手机可直接连接的云端网关。

模型输出只能是点击提示、输入提示、向前／向后滚动提示、澄清、完成建议或不支持。每次请求生成允许的“动作＋控件 ID”组合，模型从组合中选择，避免选中真实控件却配错动作；已聚焦的输入框不再允许提示重复点击，只有聚焦后才允许输入提示。代理与 Android 分别校验控件类型、ID 和输出字段。模型不能返回任意坐标或直接执行操作。

页面指纹覆盖包名、窗口 ID、控件内容、状态和位置。响应到达时重新读取页面；内容已变、会话已停或用户已暂停，就丢弃旧响应。页面变化先撤圈，再延迟至少 500 ms 合并事件；持续的页面事件不会无限推迟已排定的分析，自动请求间隔至少约 1.8 秒。相同快照不反复自动调用模型。每次会话最多分析 24 次，每次代理启动最多接受 60 次屏幕请求；这只是开发上限，不是正式用户成本预算。

焦点和窗口变化也会重新核对页面；API 33 以上在读取前清除无障碍缓存。键盘出现时，浮窗把键盘区域加入避让范围。切换系统弹窗不会继续分析其背后的页面。

## 私人内容和失败边界

本机先拦截密码字段、明显私人目标和敏感操作，代理再次校验。付款、账号登录、删除、发送／提交等不在本轮目标内。过滤不是完整的数据防泄漏系统：姓名、图片内的资料或陌生表达可能漏检。截图为单独可选项，不能宣称隐私筛查已经覆盖图像中所有资料。

页面文字是模型的数据来源，不能成为修改规则的指令。结构化输出和控件核对能阻止不存在的目标、陈旧坐标和一部分敏感操作，不能证明模型的语义判断总是正确。

目标、建议与页面快照只在当前进程中处理；结束后清除屏幕会话，不写入本机练习记录，也不自动恢复屏幕会话。设置页正在编辑的目标可能仍留在当前 Activity 内供修改。代理不主动把请求正文写入日志。供应商侧的处理与保留遵循供应商政策，不作“云端零留存”承诺。服务重绑／进程退出不会自动恢复读取。

没有把官方文档导入检索库，也没有自动采集网上教程。官方资料可在后续作为流程依据；本轮新增的是当前页面的实际模型分析链路。

## 开发与检查

安装开发依赖并启动代理的方法见[开发指南](development.md)。屏幕模式沿用同一代理与方舟密钥，不需要把密钥写入 APK。

```bash
# 宿主机代理（保持运行）
.venv/bin/python scripts/start-ai-demo.py

# 另一终端，先开启数字扶手服务，并安装 Debug、androidTest 和内部夹具
source scripts/dev-env.sh
python3 scripts/run-device-check.py screen

# 停止代理后
python3 scripts/run-device-check.py screen-offline
```

`screen` 要求模拟器已安装 F-Droid 和 Google Clock；F-Droid 首次通知提示需先处理。检查使用保留无障碍服务的 UiAutomation，真实调用模型和云端 TTS，可能产生用量。内部夹具仅用于虚构密码页的阻断检查，不是用户要安装的产品。

官方技术依据：[Android 窗口截图接口](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshotOfWindow(int,java.util.concurrent.Executor,android.accessibilityservice.AccessibilityService.TakeScreenshotCallback))、[火山图像理解](https://docs.volcengine.com/docs/ark/image-understanding?lang=zh)。运行记录会区分真实外部 App、合成输入、失败修正、播放器启动和仍未验证的体验。

本轮设备、版本、真实调用日志、截图与已知失败见[0.2.0 验收](validation/screen-guidance-2026-10-18.md)。
