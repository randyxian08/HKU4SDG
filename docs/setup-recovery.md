# 数字扶手｜首次设置、中断恢复与三语求助

2026-10-02，接续[产品质量迭代](product-quality.md)。这一轮解决两个实际问题：第一次使用时能回到选好的任务；操作被打断后，用户能决定何时继续，旧提示不会自行恢复。

## 已实现的体验

| 用户时刻 | 产品行为 |
|---|---|
| 服务尚未开启，已经选好任务与帮助方式 | 显示权限用途、系统设置三步和返回入口；保留选择，不创建尝试记录 |
| 系统开关已开，但服务尚未连接 | 显示连接状态和“重新检查”；连接前不启动任务 |
| 授权后回到应用 | 显示已准备好，返回原任务确认；仍由用户选择开始 |
| 想休息一下 | 完整、轻提示、按需帮助和结果确认卡都有暂停入口；撤圈、停播，显示继续、返回任务和未确认结束 |
| 离开目标应用到桌面或其他应用 | 清除圈画和播报；检测到持续离开后保留原尝试为暂停状态 |
| 服务关闭、应用被强制关闭或安装更新 | 再次进入应用找回原任务与帮助方式；必要时先开启服务，再主动继续 |
| 返回原任务 | 清除旧步骤缓存，重新匹配当前页面；保留会话编号，不因恢复而新建一次尝试 |
| 选择重新开始或结束 | 原尝试记为未确认结束；重新开始先回任务确认，点击开始才创建新尝试 |

运行、暂停和结束分别保存。暂停时不接受“确认完成”；恢复后还要重新核对页面和结果。系统弹窗使页面无法确认时会撤圈并停播；持续切到任务应用外才进入暂停，短暂窗口切换不直接结束任务。尚未逐一验收所有系统弹窗。

首次设置使用 Android 公开的无障碍设置入口。当前模拟器系统是英文，因此说明保留系统上实际显示的服务名和 `Use` 开关文字。数字扶手没有替用户开启权限或执行目标操作。实现对应 Android 的[服务生命周期](https://developer.android.com/guide/topics/ui/accessibility/service)和[设置入口](https://developer.android.com/reference/android/provider/Settings#ACTION_ACCESSIBILITY_SETTINGS)。

## 三语的当前范围

引导卡的步骤、展开／收起文字、重听、静音、暂停、继续和退出操作，以及首次设置、恢复页和帮助方式选项，现在跟随文字语言。普通话、粤语、英语之间切换，不改变输入语言或播报语言。语言名称保留各语言的自称。

这是按钮和文字体验。尚未加入语音口令“再讲一次、我不会、先停一下”；首页、任务介绍和记录页已在随后一轮完成三语，见[界面与端到端验收](uiux-validation.md)。真人三语输入、粤语措辞与音质、TalkBack 焦点顺序仍待验收，不能把代码中有三种文案等同于完整三语产品。

## 实际验收

设备为 Android 15 / Pixel 7 英文系统模拟器，运行 Debug APK；点击和拖动由测试人员完成。以下是开发走查，无目标用户研究数据。

| 检查 | 实际结果 |
|---|---|
| 首次开启 | 选字体任务与轻提示，服务关闭时进入设置；强制关闭应用后原选择仍在。亲手开启系统服务并返回，点击任务开始才创建尝试 |
| 返回桌面 | 字体、亮度、Chrome、Maps 启动后返回桌面，原尝试进入暂停。Chrome、Maps 主动继续后重新圈出当前登记目标 |
| 关闭服务与重连 | 运行中的字体任务关闭服务后变为暂停；恢复开关不会自行恢复运行，会话编号未增加 |
| 应用重启与更新 | 原字体尝试保留。Android 强制关闭后服务也被关闭，应用先引导重新开启；安装更新后的重连仍等待主动继续 |
| 三语控件 | 实际切换三种文字语言；输入仍为普通话、播报仍为粤语。设置与恢复页也检查了对应文案 |
| 动态大字体 | 系统字号 1.0 → 2.0 时浮层重新布局；英文暂停卡和首次设置页可读，返回按钮可操作。恢复到 1.0 后再次检查 |
| 恢复后的结果记录 | 同一字体尝试先后经历暂停、重启、服务重连；实际拖动使字号 1.0 → 1.3。检测结果与再次暂停时记录总数仍为 10；主动继续并确认后变为 11，原会话只有一条确认记录 |
| 重新开始 | 暂停的 Maps 尝试选择重新开始，原会话只有一条未确认结束记录，任务确认页保留目标与帮助；此时尚未创建新会话 |
| 构建检查 | Debug、未签名 Release、12 项 Kotlin 单元测试、9 项代理测试及 Android lint 通过。新增状态测试覆盖暂停后拒绝确认、主动恢复、结束后不能复活和空闲回调 |

修复了整行圈画的边缘裁切、已有浮层不随系统字号刷新，以及首页说明被固定输入区截断的问题。运行时截图直接从模拟器取图；活动指引期间不使用 UIAutomator，以免它重启服务影响走查。操作录像保存在飞书[进度与案例](https://my.feishu.cn/wiki/NIqHwHf98iIjqektf8KcHtdanZg)。

## 接下来怎样推进

随后一轮已加入[可维护的审核任务目录](uiux-validation.md)。目录的实现方式是：把四项任务的 App 版本、语言、前置状态、匹配条件、结果判据、审核日期和证据登记起来，遇到版本变化先暂停提供该任务，复测通过再恢复。这样扩大第三方任务时，团队知道哪里需要重新检查。

同时做三语表达和求助入口的用户走查，再挑一个日常第三方 App 场景。通讯中的语音输入、出行中的站点出口、服务查询中的公开办理说明仍是候选；先复现真实卡点再定任务。新场景应少步骤、结果可核对、容易从失败中恢复。真人研究、服务延迟、语音口令与任意 App 兼容性仍没有本轮证据。
