# 数字扶手｜火山引擎语音与受控 AI 选型

调研与接入日期：2026-09-28。已在火山引擎豆包语音新版控制台的**免费体验中心**生成普通话、粤语、英语三种语言的 TTS 样本；随后在 Default 项目开通语音合成 2.0，创建本机开发 API Key。真实 API 已分别返回三语 MP3，Android 15 / Pixel 7 模拟器中的单 App 也已向本机代理发出粤语请求并缓存播放文件。**尚未由普通话、粤语和英语使用者完成音质、语速与理解度审听，也未完成三语无障碍验收。** 本次黑客松以该模拟器为演示设备；演示证据如实标记为模拟器运行。

## 先做哪一段

先把「说出目标 → 看见识别文字 → 用户确认任务 → 在真实系统设置里亲手完成 → 收到完成反馈」做成可演示的单 App 闭环。界面与功能要一起沿这条路径打磨，不等所有页面都完美才接 AI，也不先接一个会自由生成操作步骤的语音聊天模型。

第一段界面要补齐待机、收音、识别结果预览、无法识别、用户确认、引导暂停和完成状态。始终允许手动输入与任务卡继续。语音相关能力分开替换：

```text
用户说话 ── ASR ── 用户可编辑的文字 ── 受控意图识别 ── 已审核任务 ID
                                                         │
                                             用户确认 + 已审核步骤
                                                         │
                                独立的引导文字语言 ── 独立的 TTS 播报语言
```

此处的 AI 只解决「用户说的是哪个已支持任务」；模型不生成跨应用坐标、不编造新步骤，不代替用户点击。支持范围、页面验证和完成条件由本地已审核任务决定。

## 官方接口与适用判断

| 需求 | 官方能力 | 对本项目的判断 |
|---|---|---|
| 普通话、粤语、英语语音输入 | [流式识别 2.0 选型](https://docs.volcengine.com/docs/DoubaoVoice/Accessmust-read_1?lang=zh)区分一句话识别 `bigmodel_nostream` 与实时识别 `bigmodel_async`；[单向 WebSocket API](https://docs.volcengine.com/docs/DoubaoVoice/unidirectional-streaming-automatic-speech-recognition-websocket?lang=zh)列出 `zh-CN`、`yue-CN`、`en-US`。 | MVP 是按住/点击说一句任务，优先试稳定的 `bigmodel_nostream`；结果先让用户看见和修改，再交给任务匹配。现有 App 内粤语标签为 `yue-HK`，接火山接口需明确映射到 `yue-CN`，不能直接传过去。 |
| 三语播报 | [TTS HTTP API](https://docs.volcengine.com/docs/DoubaoVoice/unidirectional-streaming-text-to-speech-http?lang=zh)有语种参数及 `explicit_dialect=yue`；使用粤语参数须选择支持方言的音色。 | TTS 2.0 / Vivi 2.0 的三语真实 API 调用已分别得到可解码 MP3；模拟器中的粤语引导也已打通云播报链路。仍须真人审听，并与 TTS 1.0 的“粤语小溏”比较。播报只读已审核文案；失败时保留可折叠文字卡。 |
| 自然语言理解 | [方舟 Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh)支持部分模型的结构化 `json_schema` 响应，官方标明该能力存在 beta 限制。 | Default 项目的 Mini 模型已单独开通；Debug 代理输出仅限 `font_size`、`screen_brightness`、`clarify`、`unsupported` 并在本机再次校验。[28 条三语测试集](intent-evaluation.md)中真实模型 28/28、本地退路 18/28；模拟器两个任务及模糊、范围外路径已走通。 |

不在第一轮接入端到端实时语音对话：当前产品需要独立控制输入、文字与播报语言，还需要用户确认及固定步骤。模块化管线更容易逐项验证错误和保留文字退路。这个顺序是团队的产品判断，不是官方对各模型效果的承诺。

## 本账号控制台实测：TTS 能生成，音质未审听

测试入口：[豆包语音新版控制台／语音合成体验中心](https://console.volcengine.com/speech/new/experience/tts?projectName=default)。测试使用与字体任务相同的简短引导意义，未输入用户录音、个人资料或页面截图。现已开通正式服务：控制台显示先消耗免费体验额度，耗尽后自动按后付费计费；当前额度与服务政策以控制台实时显示为准。

| 语言与文案 | 配置 | 控制台可观察结果 |
|---|---|---|
| 普通话：“请先打开「显示大小和文字」，再找到「字体大小」。您可以慢慢操作，需要时随时查看文字提示。” | TTS 2.0 / Vivi 2.0 / 中英混、默认 | 合成成功；44 字，播放器显示约 9 秒。 |
| 粤语：“而家請你打開「顯示大小同文字」，再搵到「字體大小」。唔使急，可以慢慢嚟。” | TTS 2.0 / Vivi 2.0 / 中英混、粤语 | 合成成功；36 字，播放器显示约 8 秒。 |
| 同一段粤语文案 | TTS 1.0 / 粤语小溏（音色库标记“粤语口音”） | 合成成功；36 字，播放器显示约 8 秒。 |
| 英语：“Please open Display size and text, then find Font size. Take your time; you can always check the written instructions.” | TTS 2.0 / Vivi 2.0 / 中英混、默认 | 合成成功；118 字符，播放器显示约 9 秒。 |

TTS 2.0 的音色库按“中英混 + 粤语口音”筛选时未显示音色，但 Vivi 2.0 的配置菜单确实提供“粤语”选项，且该模式完成了合成；音色库筛选结果不能据此判定 2.0 不支持粤语。TTS 1.0 同一筛选可见“粤语小溏”，其展示描述偏年轻、活泼。两版都需要粤语使用者判断发音、语速、亲和感、术语读法及是否显得幼稚；**目前只验证生成和时长，不宣称已经听出哪版更好**。控制台“历史”页保留了 Vivi 2.0 的三语样本，团队可在登录后逐条试听。

语音识别体验中心显示录音识别和实时识别各 20 小时试用额度，并说明支持粤语等方言；但该页需要录制或上传音频，没有现成样本。因此本次未测试普通话、粤语、英语的转写准确率，也未授予浏览器麦克风权限。下一次用公开或自制、无个人信息的三语短音频做受控测试，再与 Android 系统识别对照。

**暂定选型**：TTS 2.0 / Vivi 2.0 已作为单音色三语技术候选接入，减少演示中的音色切换；粤语若审听不达标，再比较 TTS 1.0 / 粤语小溏或重新选音色。ASR 暂定 `bigmodel_nostream`，仅有官方接口支持证据，实际效果尚未测。体验额度、正式 API 使用量与后付费账单仍须分别查看。

2026-09-28 经用户明确确认后，在 Default 项目的“开通管理”页开通语音合成 2.0。开通成功时显示剩余 **19,802 / 20,000 字**免费体验额度；本轮真实 API 与模拟器测试后复核为 **19,613 / 20,000 字**。页面提示免费额度用尽后自动消耗资源包或按后付费计费。随后在“API Key 管理”创建一枚启用状态的开发密钥，存入本机权限为 `600` 且被 Git 忽略的 `.env`，未写入 APK 或仓库。**流式语音识别 2.0 仍未开通**，用户语音输入目前继续使用 Android 设备识别服务。

同日真实 API 验证：`scripts/voice_proxy.py` 按官方 v3 TTS 请求格式使用固定音色和三语参数；火山返回多段 `code=0` 音频事件，以 `code=20000000` 结束。代理已处理该结束帧，并对不完整音频流报错。普通话、粤语、英语各一次通过本机代理返回 HTTP 200、可由 `ffprobe` 解码的 24 kHz 单声道 MP3（约 2.86、3.24、3.24 秒）；三个音频文件哈希不同。在 Android 15 / Pixel 7 模拟器的真实设置引导卡点击“再听一遍”后，代理用量减少了对应 29 字，App 缓存目录短暂出现合成 MP3，播放器完成后清理。截屏见 `captures/cloud-tts-guide.png`（本机忽略目录）。这验证了接口与模拟器播放链路，**不代表真人已经听过并确认音色质量或粤语发音**。没有代理时 App 退回本机 TTS；固定引导文字和圈画仍在屏幕上。本机 Homebrew Python 证书链与系统证书库不同，启动代理时需设置 `SSL_CERT_FILE=/etc/ssl/cert.pem`。

## 最小接入与验收

1. **无云密钥也可完成的界面闭环**：完善收音/预览/确认/失败状态；沿用文字输入和现有系统任务。录屏证明用户始终能检查识别结果、取消、重试，且权限拒绝后还能完成任务。
2. **ASR 小样本验证**：在模拟器分别提交普通话、粤语、英语的短句，记录原话、转写、耗时、失败情况。验证 `yue-HK` 到 `yue-CN` 的适配。与系统 `SpeechRecognizer` 的同句结果作对照，再决定是否替换默认路径。
3. **受控 AI 意图**：先编一组「字体调整」「容易混淆」「范围外」三语测试句；模型只从已审核任务清单选择，未知/低把握则请求澄清。记录误匹配、拒绝率与延迟；不能仅展示几个成功例子。
4. **TTS 审听**：对每种播报语言合成相同含义的短指引；记录音色、音量、语速、发音问题和无声/失败退路。粤语需真人审听，不以 `explicit_dialect=yue` 参数存在代替验证。
5. **演示回归**：在 Android 15 / Pixel 7 模拟器走完整主路径、拒绝麦克风、云服务超时、网络断开、未知页面、TalkBack 和大字模式。标明“模拟器验证”及系统版本，不外推其他设备。

调用云 API 前需在火山控制台核对该账号的新/旧控制台、已开通资源、鉴权方式、音色与实际计费；服务密钥不写入公开仓库或 APK。可由一个最小代理持有密钥，用户仍只安装一个 Android App。语音上传须在界面明确提示并取得使用者主动触发；默认不保存原始录音或页面内容。

实现分工可落在现有 [三语能力 Issue #2](https://github.com/randyxian08/HKU4SDG/issues/2) 与 [受控 AI Issue #4](https://github.com/randyxian08/HKU4SDG/issues/4)，不另起一套重复任务。
