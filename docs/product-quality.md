# 数字扶手｜产品质量迭代与下一轮取舍

2026-10-02。依据[产品定义](https://my.feishu.cn/wiki/FTF5wKcn0iNra6kG2WpcfiZ2nCg)，这一轮把“完成一次操作”补成“看见结果 → 用户确认 → 记录尝试 → 再做一次，自选帮助”。产品要持续改善的是用户的理解、控制感和重新尝试的能力。

## 这一轮已做什么

| 用户遇到的时刻 | 现在的行为 | 产品上的意义 |
|---|---|---|
| 字体已变大，但还不舒服 | 等用户确认；可以继续调整，不要求一直向右拖 | 系统数值变化和用户觉得合适是两个判断 |
| 第二次做同一件事 | 开始前自选完整指引、轻提示、自己先试试；不自动降级 | 由用户决定要多少帮助 |
| 想自己做，但突然卡住 | 按需模式不显示圈画；点“给我提示”恢复当前一步，换步后可再次主动求助 | 帮助容易找回，不强迫独立操作 |
| 想知道做过什么 | 首页“记录”进入本机最近 20 次尝试；区分确认完成与未确认结束；可以重试和清除 | 不把退出当成功，不把做过一次当学会 |
| 大字体使设置项在屏幕外 | 只在登记的设置页给滚动提示；目标出现后才圈画 | 大字体也能继续，不猜屏幕外坐标 |
| 走到未登记页面 | 撤圈并停止播报；一键返回原任务确认页 | 解释原因，同时提供可执行的退路 |
| 字体已经最大 | 提醒当前无法继续调大，允许自行去设置调整 | 不启动一个无法达成的目标 |

首页缩短标题和输入说明，标准字号可以完整看见四项任务。浮层根据目标上下方可用空间限制高度，内容过长时可滚动；按钮保留至少 48 dp 的触控高度和按钮语义，装饰圈画不参与无障碍焦点。记录仅包含会话编号、任务、帮助方式、确认结果、时间与时长；不会记录目标输入、页面、截图或录音。关闭 Android 云端备份，并在备份与设备迁移规则中排除偏好文件。未建立账号、分享或自动向支持者同步记录的功能。

## 本轮实际验收

设备仍为 Android 15 / Pixel 7 英文系统模拟器。截图是实际 APK 页面；操作由测试人员通过模拟器点击或拖动完成，服务没有代点。

- 字体实际从 1.0 拖到 1.5；检测到变化时尚未新增“确认完成”记录，点击确认后只新增一条。继续调整路径曾从 1.5 调回 1.3，滑块保持可操作。
- 轻提示初始收起文字；按需模式初始无圈画，主动求助后恢复圈画与文字。未知页面返回原任务，并记为未确认结束。
- 亮度实际由 102 拖到 188，显示等待确认；继续调整后拖回 102，仍由用户决定是否确认。亮度弹窗按当前登记控件重新匹配，避免依赖易被窗口切换清空的上一页状态。
- Chrome 更新提示出现后仍可圈出菜单；亲手保存指定网页，再打开菜单看到 Edit bookmark，等待用户确认后进入记录；关闭菜单后重新匹配当前步骤，避免沿用已完成状态。截图直接从屏幕截取；UIAutomator 读取菜单会重启无障碍服务，重启后的指引会安全停止并要求重新开始。
- Google Maps 指定中央图书馆详情中，地址行圈画可见、结果卡不遮地址；用户确认后进入记录。
- 记录在重新打开应用和安装更新后仍保留。清除时有确认框；清除后为空，三项语言设置仍保留。20 条上限、重复会话与坏数据读取由单元测试覆盖。
- 首页、任务入口、记录与清除框检查了 1.0／1.5／2.0 字体。2.0 的设置目标在屏幕外时，先按提示在卡片外滚动，目标出现后恢复圈画；字体上限提醒已实际触发。
- Android Debug／Release 构建、内部测试夹具构建、9 项 Kotlin 单元测试、9 项代理测试和 Android lint 通过。Release 产物为未签名包；本轮运行验收使用 Debug APK。

本轮没有重新测量云端 AI 准确率或真人语音能力。此前 44 条固定样本对照仍按[原评测条件](intent-evaluation.md)引用。真人粤语审听、TalkBack 朗读顺序、长者试用及延迟重做效果尚未验收，不能由上述技术走查推出。

## 下一轮先解决什么

| 顺序 | 产品工作 | 最小可验收结果 |
|---|---|---|
| 1 | 首次设置与中断恢复 | 用户看懂权限用途，能开启并回到原任务；返回桌面、系统弹窗、服务被关闭和再次进入都没有旧圈画。优先把这些路径录像记录下来 |
| 2 | 三语一致的求助体验 | 补齐操作控件语言；让“再讲一次、我不会、先停一下”在当前已审核步骤对应明确动作。先做真人三语表达与粤语审听，再决定是否扩大语音控制 |
| 3 | 可维护的审核任务目录 | 每个任务列明应用版本、页面语言、前置状态、匹配条件、完成判据、审核日期和截图；更新应用后按用例复测，通过才显示可用 |
| 4 | 日常第三方 App 场景 | 先观察用户在通讯、出行和服务查询中的真实卡点，选择一个高频、少步骤、结果可验证的任务；确认当前模拟器能稳定复现，再开发 |
| 5 | 学习效果而非完成计数 | 在同一模拟器做独立操作走查，再安排稍后重试；分别记录无帮助、提示后完成、人工帮助和失败，用实际人数作分母 |

第三方 App 的候选包括：通讯应用中找到语音输入按钮、出行应用中查看指定站点／出口、服务应用中找到公开办理说明。这些是待验证方向，不是已支持任务。通讯涉及私人会话；若不能把指引限定在本地按钮结构并可靠停止内容读取，应先选择公开查询场景。现阶段不为展示范围增加完整后台、自动代点或开放式屏幕理解。

下一轮设计判断用五个问题检查：第一次看见是否知道怎么开始；每个页面是否只有一个明确的主要动作；失败之后能否继续；三种读听说方式是否各自可用；再次操作是否能按意愿减少帮助。新增功能只有改善这些问题或验证真实高频需求，才进入开发。
