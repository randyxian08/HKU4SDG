# 数字扶手｜单 App 产品体验与功能顺序

依据[飞书产品定义](https://my.feishu.cn/wiki/FTF5wKcn0iNra6kG2WpcfiZ2nCg)（2026-09-26 版）：用户产品是一款 Android 指导应用。团队可用模拟目标做开发测试，但用户不用安装第二款“练习 App”。产品的核心不是一页宣传，也不是自动操作手机，而是“选定目标 → 确认适用范围 → 在别的应用上只指出当前一步 → 用户完成 → 验证结果”。

## 设计参照与取舍

- [Android Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3) 把颜色、字级、形状、组件和导航组织成完整系统。我们应把当前手写的色彩与按钮规范化，并逐步迁移到原生 Material 3 组件；不能仅靠大标题和圆角卡片营造“高级感”。
- [Apple Assistive Access](https://support.apple.com/guide/assistive-access-iphone/set-up-assistive-access-devcd5016d31/ios) 的可借鉴点是聚焦少数任务、放大可点目标、让支持者协助首次设置。数字扶手仍按 Android 交互设计，避免把 iOS 的外观直接复制过来。
- [Android 无障碍设计](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views) 建议触控目标至少 48 dp，并为交互元素提供可读描述。大字不能以遮住目标按钮为代价；文字、语音、TalkBack 是三条需要分别验证的路径。
- [Android 导航栏规范](https://developer.android.com/develop/ui/compose/components/navigation-bar) 适用于 3–5 个同等重要的目的地。首版只有任务、设置两处，先用清晰的首页和返回路径；等学习记录成为真实功能，再考虑固定底部导航。

首版首页的问题是“介绍产品”比“完成任务”更抢眼。现已改成一个明确的问题、一条已支持的任务及底部输入/说话入口；服务权限是一行状态与设置入口。任务详情先说清会去哪里、要做什么、适用哪台设备，再开始跨应用指引。完整对照和实机截图见[界面研究与改版依据](design-research.md)。

## 单 App 信息架构

| 页面/状态 | 用户要回答的问题 | 必要内容 |
|---|---|---|
| 首页 | 我想做什么？ | 输入/说话入口、已支持任务、引导服务状态、语言入口。尚未支持的任务不伪装可用。 |
| 任务确认 | 这是我想做的吗？ | 目标、预计步骤、适用设备/系统语言、权限说明、开始按钮。 |
| 跨应用引导 | 现在只做哪一步？ | 一处非触控圈画、默认展开的大字卡片、播报/静音/重播、收起/展开、结束。圈画不替用户点击。 |
| 暂停/异常 | 为什么停了，怎样继续？ | 私人步骤停止内容读取；未知页面立即撤圈，说明原因。恢复前重新验证当前页面。 |
| 完成 | 真的做到了吗？ | 观察真实系统结果，再让用户确认是否更容易阅读；不能只看点过按钮就报成功。 |
| 语言设置 | 我想怎样说、读、听？ | 输入、文字回复、语音播报三项独立选择；不改变任务安全步骤。 |
| 学习记录（下一阶段） | 我学会了什么？ | 只存任务状态和时间，用户可删除；不存页面原文、录音或截图。 |

## 功能优先级

**黑客松可验收的第一闭环**：一款 APK；一个在 Android 15 / Pixel 7 演示模拟器实测的真实系统任务；任务确认；跨应用定位、圈画和默认展开的文字卡；用户操作；真实结果判断；退出/未知页面清圈；三语独立设置与语音失败退路。演示中明确“已在指定模拟器验证”，不外推其他设备。

**第二闭环**：另一个经过审核的真实高频任务；私人步骤暂停与恢复的完整测试；真实用户走查；学习记录与用户主动选择的较少提示。内部模拟预约场景用于检验私人步骤，属于测试环境，不是要求用户安装的第二个产品。

**有数据和审核流程后**：AI 把自然语言映射到登记任务 ID，并解释审核过的当前动作；不会由模型即兴生成点击目标。扩展设备/系统版本、粤语 ASR/TTS、支持者协助设置及团队流程审核界面，都要按适用范围逐项验证。

## 设计验收

1. 首屏不滚动即可找到可用任务和操作入口；权限缺失时说明如何开启。
2. 任务确认页说明真实改动与设备范围；用户可以取消。
3. 目标控件无遮挡、圈画不吃触摸；卡片在大字模式仍有展开/结束入口。
4. 盲测时让目标用户独立完成，不在旁边口头补充；记录每一处误解或停顿并迭代。
5. 对外展示的截图必须来自当前可运行 APK 的真实页面，标明模拟器/真机与已验证范围。
